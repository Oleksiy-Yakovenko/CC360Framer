# CC360Framer

macOS app (Xcode project, Swift 6 language mode, macOS 14+) that opens GoPro Max 2 `.360` files, plays them with mouse look, auto-reframes around subjects and exports a flat video. See `README.md` for the user-facing description.

## Build, run, CLI
Build instructions (command line and Xcode), usage and all command-line tools / `CC360_*` environment variables are in `README.md`; keep them there and update them when behaviour changes.

Notes for working here:
- Headless/CLI modes only worked reliably through the built `.app` binary (`CC360Framer.app/Contents/MacOS/CC360Framer`). A bare binary run from a sandboxed shell printed nothing; if a batch run is silent, retry with the sandbox disabled.
- Commits end with the `Co-Authored-By` line given by the session. `.gitignore` excludes `*.app`, `**/xcuserdata/`, `*.xcuserstate`, `CLAUDE.local.md`, `*.360`, `*.sidecars/`, `*.project.json` and the legacy `*.reframe.json`, `*.analysis.json`, `*.location.json`.
- Never do direct UI testing, inspection, accessibility testing or debugging of the running app (launching it to look at windows, screenshots, UI scripting, accessibility inspection). Only do it when the user explicitly asks. Verify with the unit tests and the headless CLI tools in `README.md` instead.
- Never write into the user's footage folder (see `CLAUDE.local.md`); symlink the video and copy the `CC360Framer.sidecars` folder into the scratchpad next to the symlink (sidecars resolve relative to the unresolved path, so batch/CLI runs write only there).

## Concurrency conventions (Swift 6 mode, no `-swift-version 5`)
Both targets set `SWIFT_VERSION = 6.0`, `SWIFT_DEFAULT_ACTOR_ISOLATION = nonisolated` and `SWIFT_APPROACHABLE_CONCURRENCY = NO` (Xcode's new-project defaults are `MainActor`/`YES`; keep them as set here, the isolation annotations below rely on it). `SWIFT_UPCOMING_FEATURE_MEMBER_IMPORT_VISIBILITY` is on: import `Combine` explicitly in files that use `ObservableObject`/`@Published`/`objectWillChange`.
- UI and model types are `@MainActor` (view controllers, `PlayerModel`, `Kit`). Callbacks that AppKit/AVFoundation/Combine deliver on the main thread but declare nonisolated (Combine `.sink` after `.receive(on: RunLoop.main)`, `addPeriodicTimeObserver(queue: .main)`, `NotificationCenter` with `queue: .main`, the Metal `preDraw`) use `MainActor.assumeIsolated`; this traps if the callback is ever moved off the main thread.
- Blocking work (`Exporter`, `Analyzer`, `CutExport`) runs in `Task.detached` or on dispatch queues. Non-Sendable AVFoundation/Metal/CoreVideo objects crossing into those closures use `UncheckedBox` or a local `nonisolated(unsafe) let`, each with a comment saying which single queue touches the object. Do not add them elsewhere as a shortcut: prefer `Sendable` value types, `@MainActor`, or a lock-guarded class (`CancelFlag`, `Pacing`).
- Progress callbacks are `@Sendable`; hop to the main actor with `Task { @MainActor in ... }`.

## Project layout
- `CC360Framer.xcodeproj`: the app target `CC360Framer` (macOS 14, not sandboxed) with only `Sources/App/main.swift` (calls `CC360Main.run()`), `Sources/Assets/AppIcon.icon` and `Info.plist` (the real one: `NSDocumentClass = CC360VideoDocument`, the `dev.cc360framer.gopro-360` type and `CFBundleDocumentTypes`). It links and embeds `CCAppCore.framework`.
- `CCAppCore/CCAppCore.xcodeproj`: the framework with all other code (`CCAppCore/Sources/`, folders below) and the unit tests (`CCAppCore/Tests/`, `@testable import CCAppCore`, no host app). Only `CC360Main` (`App/EntryPoint.swift`: CLI dispatch, otherwise the app) is `public`; add `public` only for what `main.swift` needs.
- Folders use file-system synchronised groups: add or move files on disk, no project edit needed.
- Build: `xcodebuild -project CC360Framer.xcodeproj -scheme CC360Framer build` (or the Xcode MCP `BuildProject`). Tests: `xcodebuild -project CCAppCore/CCAppCore.xcodeproj -scheme CCAppCore test` (or `RunAllTests`).

AVFoundation rejects the `.360` extension (`-11828 Cannot Open`), but `AVURLAsset(url:, options: [AVURLAssetOverrideMIMETypeKey: "video/mp4"])` opens it directly (verified: playback, analysis reader and export all work), so `PlayerModel.loadAsset` uses that first and falls back to a temporary `.mp4` symlink in a per-model unique temp dir (`playableURL`; `CC360_FORCE_SYMLINK=1` forces the fallback). The Diagnostics CLI tools still use their own symlinks. The app's `Info.plist` declares the `dev.cc360framer.gopro-360` type (extension 360, conforms to `public.movie`) and `CFBundleDocumentTypes`; the open panel accepts `[.movie, .data]`.

Maps a rectilinear view (yaw, pitch, vertical fov, stabiliser basis) onto the two-ring EAC layout; feathered 64 px tile overlaps; display-link driven; `ViewState` and `Uniforms` (Swift and MSL layouts must match). Export-frame guide (`Renderer.encode(showGuide:)`, preview only): `ExportFrame` (pure) gives the frame (`halfExtent`, `pixelRect`) and `previewFovScale` = 1/hy, which multiplies `tan(fov/2)` so the frame spans exactly the exported field of view; `ViewState.fovDegrees` and keyframes stay the real fov, `LookView` uses `previewFovDegrees` for drag sensitivity, and overlays are laid out inside the frame (`OverlayLayout.rect(... frame:)`, rasterised for the frame's short side).
- `Telemetry.swift`: MP4 `moov` walker and GPMF parser for the `gpmd` track (`CORI`, `GRAV`, `IORI`), one sample per frame.
- `Stabilizer.swift`: per-frame virtual camera basis from gyro/gravity-anchored orientation (modes off/level/smooth); `toVirtual`/`toBody` convert directions. Axis mapping `sensorToRender = (1,-1,1)` was calibrated visually; do not change it without re-checking max-lean and max-pitch frames.
- `Analyzer.swift`: renders 8 level horizon views (512x512, fov 90) from quarter-res decoded frames every 6th frame; Vision person and saliency requests; stores detections in body frame (mode independent) as `[Observation]`.
- `Styles.swift`: `PathStyle` (`.follow`, `.scenery`) and `SceneryPlanner` (forward, side glances, rare rider shots: at most 2, at least 60 s apart, only when no side slot is interesting; candidates near the rider are ignored).
- `CameraPath.swift`: `PathBuilder` (grid, median, Gaussian smoothing, speed limit, keyframe decimation) and Hermite `CameraPath`.
- `ExportSettings.swift`: Codable value (container, codec, rate control, resolution, aspect, crossfade) with the computed even `outputSize` and AVAssetWriter settings; lenient decoding; defaults in `UserDefaults` (`exportSettings`), per file in `ProjectSidecar.exportSettings`. Edited by the shared `ExportSettingsView` (UI/; right sidebar Export tab, reusable by the batch window).
- `TimeMap.swift` (`Reframing/`): pure `CutRegion` + `TimeMap` (kept segments, output<->source time, `sample(atOutput:)` giving the frame(s) and dissolve weight; crossfade = overlap of kept material, effective fade <= half of each neighbouring segment). `CutExport.swift`: per-segment `FrameFeed` readers and the BGRA blend used for dissolves. `Export/AudioExport.swift`: the export's audio, ONE composition with the enabled .360 tracks (two lanes per track with dissolve volume ramps when there are cuts) plus one composition track per audio-clip piece, ONE `AVAudioMix`, built by `AudioExport.build(source:trackIDs:map:sourceDuration:clips:)`; the pure `Audio/AudioMixPlan.swift` (tested) intersects clips with the kept segments (clips are positioned in SOURCE time, so after a cut the music jumps with the video; fades continue across cuts; dissolve ramps; pieces shortened to the file length; unusable clips skipped). Start values of volume ramps are set in the gap before them (a value set exactly at a ramp start glides in from the old value, a ~25 ms burst); `AudioExportTests` reads the mix back offline from generated WAV files. With cuts the exporter renders each output frame at its source time (second render + CPU blend during a dissolve); without cuts the old single-reader path is unchanged.
- Preview skipping: `PlayerModel.updateCutPreview` installs an `AVPlayer` boundary observer at each cut start (`TimeMap.jumpPoints`, crossfade 0) and `skipCutIfNeeded` seeks to the end of the cut; `togglePlay` also skips when starting inside a cut. Needs a manual check in the app (not covered by tests).
- `Exporter.swift` (`audioClips:` parameter, returns the number of skipped clips; the audio uses its own composition and reader when there are cuts or clips; the no-cut, no-clip path still reads the source tracks directly): reads the composition, reprojects with Metal per frame, writes HEVC/H.264 + AAC per `ExportSettings`.

The MAIN player is the master (its composition, audio mix and the dissolve spare are never touched): `PlayerModel` calls `play(at:)`/`pause()` (togglePlay, end of video, cut skip to the end), `scrub(to:)`/`seek(to:)` (scrub/endScrub, which also carry cut skips) and `stop()` (open, cleanup); after every seek/rebuild the clip player is positioned paused and a 0.1 s timer starts it only once the main player really runs (`rate > 0` and `timeControlStatus == .playing`), 0.05 s ahead; drift < 0.03 s is ignored, up to 0.5 s it is removed by nudging the clip player's rate by +/-4 % (hysteresis, time-domain pitch), only larger jumps re-seek (a hard re-seek restarts the audio and used to repeat every check: the periodic volume wobble after a seek). `PlayerModel.audioClipsAudioChanged()` (after every clip change): volume/fade-only edits swap `item.audioMix` in place (`AudioExport.remix`, `AudioClipSync.needsRebuild`), other changes rebuild the item debounced 0.3 s on a detached task (`RebuildGate` drops stale results). The folder is created on save, never on load; loading falls back read-only to the legacy file next to the video (`<file>.<kind>.json`). All sidecar IO goes through `Sidecar`.

## File format facts
- Each track is 5888x1920, a ring of three 90° EAC faces (tiles 992/3904/992, 64 px overlap). Track 0 ring about the vertical axis (front = yaw 0); track 1 ring about the horizontal axis (rider in its "back" face, stored rotated 90°).
- Telemetry: `CORI` orientation quaternion, `GRAV` gravity, `IORI` roll-only image orientation (applied forward). Fov is vertical, default 70°.
- Remaining ~0.7° wobble at 0.5-2 Hz is translation parallax; rotation cannot remove it.

## UI conventions
- No subtitle/caption labels in the sidebars. Explanations go in the tooltip (`toolTip`) of the title label (`Kit.title(_, tip:)`) or of the control. A conditional status note (secondary colour, wrapping, hidden unless it applies, e.g. under "Automatic card at start" while card keyframes exist) is allowed: it reports state, it is not a subtitle.
- Build controls with the `Kit` helpers in `ViewKit.swift` (grid rows, colour well, font popup, `TabContainer`).
- Alignment rule: every settings page of the right sidebar (and the batch window) is laid out with `Kit.grid([...])`, a two-column `NSGridView` with a shared label column (`Kit.labelColumnWidth`, labels right-aligned, so each label sits next to its control) and a controls column where ALL controls start at the same x. Rows: `Kit.row(label, control, tip:, fill:, top:)` (`fill: false` for fixed-size controls such as colour wells and size combos), `Kit.checkRow(view)` (empty label cell; checkboxes and buttons, text is the checkbox title), `Kit.fullRow(view)` (spans both columns, e.g. a section title inside a grid). Section titles, wrapping notes and progress bars sit in the `Kit.sidebarStack` outside the grids. Hide a row with `GridRow.isHidden`, not by hiding its views. Keep labels short enough for the 88 pt label column (sidebar minimum width 280).
- Destructive actions (clear, delete) ask for confirmation with an `NSAlert` and are undoable through `PlayerModel.undoManager`. Undo design: `SnapshotUndo` (composition) owns no `UndoManager` and never changes `groupsByEvent`; it registers on the manager its provider closure returns. Never create a private UndoManager with `groupsByEvent = false` or window-delegate overrides: NSTextView (`allowsUndo`) registers on the window's manager and would throw 'must begin a group'.

## Tests
- **Fix all compiler warnings before committing**: a clean build of both projects and the test run (check with a full rebuild, since incremental builds hide warnings) must produce zero warnings, not just zero errors.
XCTest target `CCAppCoreTests` (`CCAppCore/Tests`, `@testable import CCAppCore`, runs without the app). It covers the pure logic: `CameraPath`/`PathBuilder`, `PathStyle`/`SceneryPlanner`, `Stabilizer`/`Gaussian`, overlay alpha/placement.
- **Add test coverage for every piece of new or changed logic** (anything not tied to Metal, AVFoundation or UI), in the matching `*Tests.swift` file. Fix bugs with a regression test.
