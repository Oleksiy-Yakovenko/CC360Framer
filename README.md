# CC360Framer

macOS app that opens GoPro `.360` files (tested with Max 2), plays them with mouse look, auto-reframes them around a detected subject and exports a flat video. Requires macOS 14+.

## Build and run

Command line:

    ./build.sh && open CC360Framer.app
    CC360Framer.app/Contents/MacOS/CC360Framer GS010074.360     # open a file on launch

`./build.sh` makes a release build wrapped as an ad-hoc signed `CC360Framer.app`. You can also use `swift build` (or `swift build -c release`) and `swift run CC360Framer file.360`; these run the bare binary without an app bundle. The new macOS (Liquid Glass) look needs a binary linked against SDK 26 or later, but SwiftPM records the deployment target (14.0) as the SDK version; `Package.swift` therefore passes a linker flag that keeps `minos 14.0` and records SDK 26.2, for every build path (`swift build`, `./build.sh`, Xcode). Check with `vtool -show-build <binary>` (`minos 14.0`, `sdk 26.2`). The app icon (`Sources/CC360Framer/Assets/AppIcon.icon`, an Icon Composer file) is compiled by `build.sh` with `xcrun actool` into `Contents/Resources` (`Assets.car` for macOS 26+ plus an `AppIcon.icns` fallback) and referenced from the generated `Info.plist` (`CFBundleIconName`/`CFBundleIconFile`); if actool fails the build continues without an icon. The folder is excluded from the SwiftPM target. A plain `swift build` / `swift run` / Xcode run of the package executable has no app bundle and shows no icon (Xcode does not apply the `.icon` to a SwiftPM package executable). The package uses Swift 6 language mode (swift-tools-version 6.0; Xcode 26 or a Swift 6 toolchain).

Run the unit tests with `swift test`.

Xcode:

- `open -a Xcode Package.swift` (there is no `.xcodeproj`; Xcode opens the SwiftPM package directly).
- Pick the `CC360Framer` scheme and "My Mac", then Cmd+B to build or Cmd+R to run.
- To open a file or set `CC360_*` variables: Product > Scheme > Edit Scheme > Run > Arguments / Environment Variables.

## Using the app

- **Open:** File > Open (multiple files allowed), File > Open Recent, drag one or more `.360` files onto a window, double-click a `.360` once the app is built with `build.sh` (it declares the type), or pass one as an argument. Every file is a document with its own window and settings (the app uses the standard document system); opening a file that is already open just brings its window forward. Menu items and shortcuts act on the front window. Closing the last window does not quit the app (a running batch keeps going); open files from the menu or the welcome window.
- **Welcome window:** shown at launch when nothing gets opened, when the Dock icon is clicked with no windows, and any time with Window > Welcome to CC360Framer (Shift-Cmd-1). It lists the recent files (name and folder; files that no longer exist are left out); double-click or Return opens one, *Open…* shows the open panel, Escape closes it. It closes when a document opens.
- **No save prompts:** a file window is a viewer; every edit (keyframes, cuts, captions, card, settings, direction lock) is written to the sidecars as you make it, also by undo and redo, and anything still waiting on a short timer is written when the window closes or the app quits. A document is never marked as modified, so closing or quitting never asks to save.
- **Reopening and window layout:** the files that are open when you quit are reopened at the next launch (files that no longer exist are skipped; closing a window yourself forgets the file). Every file remembers its window frame and the widths and collapsed state of its sidebars (saved in the app's preferences, keyed by file path). Launching with a file argument or `CC360_DEBUG` opens just that file and neither reopens nor changes the remembered session.
- **Look:** drag to look around, scroll/pinch to zoom, double-click to reset. Audio tracks are toggled individually in the right sidebar's Audio tab.
- **Analyse:** projects 8 views (default) around the horizon, detects people and (on the side views) salient objects, and stores the raw detections next to the video (`CC360Framer.sidecars/<file>.analysis.json`). A path style turns them into a smoothed camera path of editable keyframes (diamonds on a black strip above the seekbar), saved as `CC360Framer.sidecars/<file>.reframe.json`. Sidecars live in a `CC360Framer.sidecars` folder created next to the video on first save; sidecars from older versions next to the video are still read (never written). Re-analyse asks for confirmation because it takes minutes. The **Analysis quality** drop-down (app default, applies to the next analysis, so re-analyse to use it) trades time for recall: *Fast* = 8 views of 90° (about 1x time), *Medium* = 12 views of 60° (about 1.5x), *Best Quality (slowest)* = 16 views of 45° (about 1.8x). Narrower views make small and distant people larger for the detector, so crowds and far-away people are found far more often (on a test row of 24 children: about 8, 17 and 21 found). Person scores are scaled by the view's solid angle so path styles behave the same at every quality (salient-object scores are not scaled; Medium and Best analyses made with earlier builds have too-low salient scores and gave scenery paths without side glances, so re-run them). Batch has its own *Quality* setting (CLI `--quality fast|medium|best`). Since this version the analysis also stores each detection's box (4 corners); older analyses still load but need a re-analysis to get boxes. The left sidebar checkbox **Display detected subjects** (app default, preview only, never in export) outlines people in green and salient objects in yellow over the preview, at the nearest analysed frame (about 5 per second; nothing between analysed ranges). The overlay merges duplicate detections from overlapping views and draws a cyan dashed box around groups of 3 or more people (display only; path building is unchanged). Detections without boxes show as small crosses.
- **Style** (drop-down, remembered between launches): *Follow subject* keeps the main subject (the rider) in view. *Scenery + rider* looks forward along the direction of travel and glances at objects on the sides. The rider is shown rarely: at most twice per clip, at least a minute apart, and only when nothing else is interesting. In both styles the camera only follows people and objects that stay detected for at least 2 seconds (briefer detections are ignored when the path is built; the detections overlay still shows them). Switching style regenerates the path from the stored detections without re-analysing (it asks first if you have hand-edited keyframes: use **Build path**).
- **Direction lock** (checkbox under the style; per file; replaces the earlier Forward setting and its accelerometer/GPS estimate, which are gone): the camera is often mounted at an angle to the direction of travel. Rotate the preview (drag) to the direction you consider forward; about 0.4 s after you stop dragging that direction (yaw only, in the stabilised view; zoom does not count) is remembered, also while the lock is off, and defaults to the camera front (yaw 0) if you never rotated. Ticking the lock does not move the view: forward becomes the last direction you set. While ticked, that direction is used for the Scenery forward shots and as the reference for the side glances (left/right and the 35-145 degree range are measured from the locked forward, not from the camera front; the rider exclusion and the analysis, which skips saliency within 45 degrees of the camera front/back, stay camera-relative) (with the lock off they look at the camera front, yaw 0), for the double-click reset in the preview, and for the initial view when the file is opened. Ticking it regenerates the path like changing the style (or asks you to press Build path if you hand-edited keyframes); dragging afterwards does not rebuild by itself. Both values are saved in the project sidecar (`directionLock`, `lockedYaw` in radians). Batch (window and `--batch-run`) uses the file's saved lock when it builds a path. The default export view without keyframes already uses the current preview direction.
- **Stabilise** (drop-down, default *Level + smooth*): uses the camera's own motion data (`GRAV` gravity and `CORI` orientation from the file's `gpmd` track) to keep the horizon level and remove shake. *Level* locks the horizon only; *Level + smooth* also smooths the heading. Look directions and keyframes are relative to this stabilised camera, so pitch 0 is the horizon. Field of view defaults to 70° vertical (wider looks stretched at the edges). Works without analysing.
- **Location card:** the first GPS fix in the file is reverse-geocoded (needs network once; cached as `CC360Framer.sidecars/<file>.location.json`) and shown for the first 10 seconds (placement: any corner, top/bottom middle or centre; plus font, size (an editable drop-down: pick 24 to 160 or type any number from 8 to 400), text colour and outline, all in the right sidebar's Location tab and saved per video in `CC360Framer.sidecars/<file>.project.json`; changes can be undone) as country, city, coordinates and elevation (when the GPS reports one), in both the preview and the export. Card and caption text is rasterised at the pixel size it is drawn at (a card font size of 64 means 64 px in a frame with a 1080 px short side and scales with the frame; captions use their % of the short side), (outlined text is drawn in two passes, a round-joined stroke of twice the outline width and the fill on top, so the outline is a clean outer border of exactly the stated width; `OutlinedText`), so it stays sharp at any preview window size, on Retina displays and at every export size: the preview re-rasterises shortly after the window size settles (until then the previous bitmap is scaled), the export once for its output size. The Location tab chooses the content: *Show location card* (master switch, default on; off hides the automatic card and all card keyframes in preview and export) and per-field checkboxes Country, City, Street, House number (shown as "Street 12" on its own line above the city; needs Street), Coordinates, Elevation (defaults: Street and House number off, the rest on). The fields apply to all cards, are undoable, saved per video (`showLocationCard`, `locationFields` in the project sidecar; older sidecars use the defaults) and used by batch runs. Location caches from older versions (one combined place text) show that text as the city at once and are looked up again in the background; when the lookup answers, the card and the cache are updated (offline the old text stays). An export or batch run waits at most 5 s for a running lookup, then uses the card it has. Files without a GPS lock show nothing. **Location card keyframes:** the bottom bar's popup has a *Location cards* timeline (Add card at the playhead, Delete, Clear, previous/next; diamonds under the seekbar). Each card keyframe shows the card for 10 s (with fades) from its time with the Location tab's placement by default (new cards inherit it and follow when it changes); tick *Override placement* in the Inspector tab to give a card its own placement (undoable; the popup shows the inherited value, disabled, while unticked). Sidecars from earlier versions stored a placement per card; those stay explicit overrides. The look stays global. Without card keyframes the automatic card at 0 s is shown (switch it off with *Automatic card at start* in the Location tab); once at least one card keyframe exists only the keyframes are used (add one at 0 s to keep a card at the start; a note under the checkbox says so while card keyframes exist). A later card keyframe replaces an earlier one that is still visible. Card times are source times, so they work with cuts, and are saved in the project sidecar (`locationCards`, `autoLocationCard`).
- **Captions:** the bottom bar's popup has a *Captions* timeline (Add caption = 3 s at the playhead, Delete, Clear, previous/next; bars with draggable edges under the seekbar, like cuts; captions do not overlap). The Inspector tab edits start/end, the text (several lines) and per-caption overrides of placement, font, size (% of the frame's short side), text colour, outline colour and outline width (% of the font size); empty/Default fields inherit. The default look (placement, font, size as an editable drop-down of percentages 2 to 15, colours, outline; default bottom centre, bold white with a black outline, 5.5 % of the short side) is edited in the Export tab's *Captions* section, saved per video (`captions`, `captionStyle` in the project sidecar) and as the app default for other videos. Captions fade in and out over 0.2 s, are shown together with the location card, use source time (so they follow the cuts) and appear identically in the preview and the export. Lines are only broken where you type a line break; text wider than 90 % of the frame is scaled down.
- **Edit:** `K` sets a keyframe from the current view, click a diamond to select it, `Delete` removes it. Dragging, scrolling or pinching the view switches off Auto (trackpad momentum and zero-movement events are ignored) and the status line says so; press Auto to follow the path again. Delete key and Clear keys ask for confirmation. Edit > Undo / Redo (Cmd-Z, Shift-Cmd-Z) cover keyframe changes, Build path and the location card placement. Space, K and Delete are ignored while a text field is being edited.
- **Timelines:** the popup at the bottom left picks the active timeline: *Keyframes* (camera) or *Cuts* (parts removed from the export). The seekbar markers, the Add / Delete / Clear buttons (with confirmation for delete and clear), previous/next and the Inspector tab all follow the selection. Cuts are bars under the seekbar: *Add cut* creates a 3 s cut at the playhead (clamped to the clip, never overlapping another cut), click a bar to select it and jump to its start, drag its left or right handle to resize (it stops at neighbouring cuts), or type start and end in the Inspector. Everything is undoable and saved per video in the project sidecar.
- **Cuts in the export:** cut regions are removed from the exported video and audio; the output PTS stay contiguous. At each cut between two kept parts the crossfade length from the Export tab (0 = hard cut) is a real dissolve: the end of the earlier part and the start of the later part overlap by that length (video blended, audio volume ramps), so only kept footage is ever shown and every interior cut makes the output shorter by the crossfade (`output = source - cuts - crossfades`). The crossfade is limited to half the length of each neighbouring kept part; a cut at the very start or end has no dissolve. Camera path, stabiliser, location card timing and telemetry use the source time of each output frame.
- **Preview with cuts applied** (checkbox in the Export tab, saved per video): playback jumps over the cut regions with the same crossfade as the export (a second muted player shows the incoming part; the renderer blends both frames with the export's ramp, audio volume ramps, then the players swap) and stops at the end of the clip; the seekbar still shows the whole source video and you can scrub into a cut. Known limitation: the preview crossfade may hitch briefly at the start of a dissolve (the incoming frames can arrive a few frames late).
- **Record camera moves:** the red dot button right of Play is a toggle (filled dot and pushed look while on; off when a file is opened, never saved with the file; enabled once a file is open). While on, every drag, scroll zoom or pinch in the preview adds keyframes, during playback and when paused: an anchor key with the view as it was before the move, then about 4 keys per second (at most one per 0.25 s) while you keep going, and a final key when you stop (no movement for 0.4 s). Existing keyframes inside the time range you passed over are overwritten by the recorded ones (keys outside are untouched; a key within 0.15 s of the range is replaced, as with `K`). The recording is one undo step (Edit > Undo "Record Camera"), Auto is switched on afterwards so the path follows the recorded keys, and the keyframes are saved once at the end. With Global FOV on, only yaw and pitch change (zoom is disabled).
- **Inspector:** select a keyframe and edit its time, yaw, pitch and field of view numerically in the right sidebar's Inspector tab (Enter commits; undoable; keyframes are re-sorted).
- **Export:** HEVC or H.264 + AAC in an MP4 or MOV container, using the audio tracks currently toggled on. The right sidebar's Export tab sets format, codec, rate control (average bitrate in Mbps, empty = automatic: 20 Mbps up to ~3 MP and 50 Mbps above; or an encoder quality level), resolution (short side 720p / 1080p / 1440p / 4K, or a custom width), aspect ratio (16:9, 9:16, 1:1, 4:5, 4:3 or custom w:h; the output size is rounded to even pixels and shown in the tab) and the cut crossfade length. The settings are saved per video in the project sidecar and as the default for other videos. "Show export frame" outlines the exported area in the preview and dims the rest (preview only, never in the file). The frame is always the largest rectangle of the export aspect that fits in the view, and while it is shown the preview is drawn so that the area inside the frame is exactly what the export contains (same field of view, any window size); the dimmed surroundings show extra context, and the location card and captions are placed inside the frame as they will be in the export. Zoom and mouse look keep working on the real field of view. **Global FOV** (checkbox and 20-140° slider with an editable value field; every slider in the sidebars has one, type a number and press Return, saved per video and as default) replaces the field of view of every keyframe in the preview, the export and batch runs; while it is on, scroll and pinch zoom in the preview are disabled (the slider is the control). Choose Actions > Export… (⌘E) to write the file. The sidebars can be hidden with the toolbar toggles (left: ⌃⌘S, right: ⌥⌘2).

Limits: rotation compensation cannot remove shake caused by camera translation (small residual wobble at 0.5–2 Hz). HiLight tags and gyro/accelerometer data are not used yet (only orientation, gravity and the first GPS fix).

## Batch processing

Window > Batch Processing... (Shift-Cmd-B) opens one shared window. Drop `.360` files or folders on the list (folders are searched recursively, duplicates ignored) or use Add...; drag rows to reorder, Remove/Delete removes the selected rows, Clear empties the list. Start processes the files one after another; Pause finishes the current file and stops (Resume continues, failed files are retried).

- Force re-analyse: analyse again and rebuild the camera path. Off: an existing analysis is reused and existing keyframes (also hand-edited) are kept; files without analysis are analysed.
- Export: off = only analyse and build the path (keyframes are saved as usual).
- Path style, output folder (required for export, never defaults to the footage folder; exported as `<name>-reframed.<ext>`, `-2`, `-3`... on collisions) and the export settings (same editor as the Export tab, stored separately from per-video settings) apply to the whole batch.
- Cuts, captions, location cards and the global fov of each file come from its own sidecars; sidecars are written next to each source file as usual.

## Command line tools and debugging

- `--batch-run [--out DIR] [--force] [--no-export] [--style follow|scenery] [--settings EXPORT_JSON] FILE_OR_FOLDER...`: the batch engine without UI (settings are not saved).

- `--telemetry file.360`: print parsed telemetry counts and first/last samples.
- `--telemetry` also prints the first GPS fix with its altitude (median of the first locked fixes, GPS height in metres).
- `--snapshot stacked.png prefix`: render projection test images. Env: `CC360_TELEMETRY=file.360 CC360_TIME=sec CC360_MODE=level|smooth CC360_AXES=1,-1,1` to apply stabilisation.
- `--stab-test file.360 [start] [length]`: measure residual shake per stabilisation mode and the telemetry/video time offset (env `CC360_SIGMAS`, `CC360_SCAN`, `CC360_W`).
- `--analysis-compare file.360 [start] [length]`: compare analysis on the raw versus level frame.
- `CC360_BATCH=out.mp4` with a file argument: headless analyse (or build from cached analysis) and export. Add `CC360_STYLE=scenery` for the scenery style, `CC360_NO_ANALYSIS=1` for a plain stabilised export without keyframes.
- `CC360_EXPORT_SETTINGS='{"container":"mov","codec":"h264","aspect":"1:1","resolution":"720p"}'` with `CC360_BATCH`: export with these `ExportSettings` (JSON, any subset of the fields; the rest come from the saved settings).
- `CC360_GLOBAL_FOV=deg` with `CC360_BATCH`: export with the global fov override set to this vertical fov (not saved).
- `CC360_FORCE_SYMLINK=1` opens `.360` files through a temporary `.mp4` symlink instead of directly (the fallback path).
- `CC360_DEBUG=1` autoplays and logs frame rate; `CC360_PACING=sec` reports frame pacing then exits (`CC360_NOPLAY=1` skips play); `CC360_NOBLIT=1` skips compositor blits.
